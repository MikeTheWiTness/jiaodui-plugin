# ADR 0006：报告正文 v2 的无损标记编码与信封边界

- 状态：已采纳
- 相关：[PRD](PRD.html) §5.2、[PLAN-rework-continuation](../PLAN-rework-continuation.md) P3/D2、[ADR 0004](0004-gate-single-implementation.md)、执行计划 §11.1/§11.2

## 背景

内联标记语法是 `【编号|原文|改为】`，字段规则为：

```
INLINE_MARKER_CAPTURE_RE = 【(\d+)\|((?:\\\||[^|])*)\|([^】]*?)】
```

三个实测问题：

1. **原文字段允许 `\|` 但没有任何反转义**：`split_marked_body` 把原文字段**逐字**回填，所以老报告里的 `\|` 重建出来仍是 `\|`。写进去的转义读不回来，转义形同虚设。
2. **改为字段是唯一无法容纳字面 `】` 的字段**：`[^】]*?` 遇到字面 `】` 直接截断，字段内容被腰斩。
3. **因此 v2 链只能硬拒绝三类内容**（`report_suggestions.py:205` 源文含标记语法、`:233` 原文字段含 `|`/`【`/`】`、`:234` 修改后含 `【`/`】`），把**编码能力不足**变成**流程拒绝**：单元还没到闸门就先失败，和"拿不到校对结论"混为一谈。

这些字符在物理讲义里真实存在：绝对值与集合表示用 `|`，被标记的括号、并集符号、题干里的 `【】` 都是正文。

另一件必须一起定下来的事：`body_sha256` 与 `source_sha256` 现在由**同一个值**校验（`report_suggestions.py:202` 两个字段都对 `source_digest(source_text)`；`unit_delivery.py:56-57` 一个取文件字节、一个取解码文本），因此无法表达"正文之外还有信封"，也无法在诊断里说清是**源文文件变了**还是**正文变了**。

## 决策

### 1. 只有 v2 报告启用转义，v1 逐字不变

以报告首行 `<!-- jiaodui-report-v2 -->` 判定，唯一判据函数 `is_v2_report(text)`，替换现有散落的字符串字面量（`verify.py:453`、`report_parse.py:194`、`split_sections`）。

- v2：字段写入前转义，字段读出后反转义。
- v1：**不转义也不反转义**，`\|` 保持字面。旧语料回归与既有拒绝集合逐份不变。

### 2. 转义规则（唯一实现）

`markers.escape_marker_field` / `markers.unescape_marker_field`：

- **转义**：先 `\` → `\\`，再 `|` → `\|`、`【` → `\【`、`】` → `\】`。顺序不可交换（先转义反斜杠，否则会把新引入的转义符再转一遍）。
- **反转义**：从左到右扫描；`\` 后跟 `\`、`|`、`【`、`】` 四者之一 → 还原该字符并跳过两位；`\` 后跟其他字符 → `\` 与该字符都原样保留（保护 LaTeX 命令如 `\frac`、`\mathrm`）。
- 不变量：`unescape(escape(s)) == s`；`escape` 单射（不同输入不会编码成同一字段）。

### 3. 语法随之扩展：字段可以包含转义分隔符

```
【(\d+)\|((?:\\[\s\S]|[^|])*)\|((?:\\[\s\S]|[^】])*?)】
```

- 原文字段：`\` 加任意字符视为一个整体，`\|` 不再终止字段。
- 改为字段：同样允许 `\】`，修掉"唯一无法容纳字面 `】`"的字段。
- `_MARKER_MASK_RE`（公式扫描的屏蔽用正则）同步扩展，否则含 `\】` 的标记会被提前截断，`scan_math_spans` 会把标记字段内的 `$` 当成真公式。

#### 3.1 语法检查只看结构，字段内容一律屏蔽

允许字段含字面括号之后，"括号配对"与"字段数"两项检查必须只统计**结构**分隔符，否则合法报告会被自己的内容判死：

- `【1|\【注\】|〔注〕】` 的字段内容带 `】`，若把内容里的括号计入配对，一份合法报告会被判 `syntax.unbalanced-brackets`；
- 旧的字段数检查用 `【\d+[^】]*】` 取块，遇到字段里的 `\】` 会**提前截断**，于是 `【1|A\】B|C】` 被数成 1 个竖线 → 误报 `syntax.field-count`。

实现：`markers.mask_marker_fields(text)` 把字段内容替换为**等长**占位，只保留 `【`、编号、结构竖线和 `】`；语法检查在屏蔽后的文本上做结构判定，**诊断片段仍从原始正文按同一偏移截取**（长度不变，偏移对齐）。
`verify-report` 的严格度不变：屏蔽不是放宽，只是把"字段内容"从结构判定里排除。

**v1 边界说明**：`\` 加任意字符视为整体，会让 v1 里"改为字段含 `\】`"这种极端写法解析出更长的字段（旧实现会在 `】` 处截断）。实测冻结语料中**没有一份**报告含该写法（`grep '\\】' ../JiaoDuiAgent/output` 命中 0），旧语料回归 7/7 通过，故不视为行为变更；若将来出现该类历史报告，按"v1 不转义"原则逐份标注预期，不得静默改变。

### 4. 谁读谁写：四个消费点共用同一对函数

| 位置 | 角色 | v2 动作 |
| --- | --- | --- |
| `report_suggestions.render_suggestions` | 写 | `escape_marker_field` |
| `markers.split_marked_body` | 读（重建正文） | `unescape_marker_field` |
| `markers.audit_markers` | 读（真实性审计） | `unescape_marker_field` |
| `report_parse._parse_inline_format` | 读（corrections 内容） | `unescape_marker_field` |
| `docx_report` 字段提取（`_mask_markers`） | 读（渲染与批注） | `unescape_marker_field` |
| `report_repair`（v1 专用） | 读写 | **不启用**；它已拒绝 v2 报告（`repair.v2-not-supported`） |

函数签名统一带显式 `escaped: bool = False`，**v1 默认**。每个调用点必须写明自己的语义，禁止在函数内部猜报告版本。

语义分界：**进入"内容"语义（corrections、批注、重建正文、原因引用）必须反转义；保持"报告字面"语义（`_校对数据.json` 的 `marked_text`、字节级长度记账）不反转义。**

### 5. 不放宽任何拒绝

转义只扩大**可表达字符集**，不放松判定。以下全部保持拒绝：空原文字段、空操作（原文 == 改为）、无唯一位置、区间重叠、乱序、`split_marked_body(正文) != 正文`。`verify-report` 仍是唯一闸门，字段内转义不能成为绕过闸门的通道（转义由写入侧生成，读取侧对称还原，双方不共享绕过路径）。

## 信封边界

### 6. v2 正文 = 单元源文文本全文；信封只存在于 v1 报告

- 实测：回放材料与冻结语料里**没有一份源文含 `## 前置参考`**。`前置参考` / `### 权威原文` / `### 字面差异` / `⚠️` / `编号：` / `内容：` 都是 **v1 报告**里模型自加的装饰，只由 `strip_reference_preamble` 在 v1 读取路径剥离。
- v2 报告不剥任何东西（`verify.py:453` 已按 v2 跳过 `strip_reference_preamble`），因为闸门依赖"标记原文 == 源文字面"的严格相等；剥任何一行都会让这条不变量失效。
- 因此 **v2 报告没有信封，只有正文**；"信封"在本 ADR 里专指 v1 报告的装饰层。

### 7. 两个摘要分工：当前取值相同，绑定语义不同

| 字段 | 绑定对象 | 用途 |
| --- | --- | --- |
| `source_sha256` | 源文**文件字节**（`material.sha256(path)`） | CAS、快照失效判定 |
| `body_sha256` | **正文文本**（`sha256(extract_body(源文文本))`） | 断言报告标记原文 == 正文 |

- 正文提取只有一处 `extract_body(text)`，当前是恒等函数。将来真要引入源文侧信封（例如导入器写死的抬头行），只改这一处，**不动 CAS 契约与任何调用方**。
- 提交时**分别校验**两个摘要，并让 `proposal.source-mismatch` 的详情指明是哪一个对不上（现在两者共用一个 `digest`，无法区分）。

### 8. 空正文显式拒绝，短正文不算空

- 正文为空白（空串或全空白）→ 提交拒绝，错误码 `proposal.empty-body`，提示该单元应显式 skip；**不得**静默产出一份 `### 标记原文` 为空的报告——那会让闸门对着一份空报告放行。
- **非空白即正文**：实测回放 4讲 单元1 的源文是 `第 4 讲\n\n【选修专项】简谐运动与机械波`（21 字符）。它是很短的真单元，属"有正文"，正常生成报告，不得当成信封剥掉。

## 影响

- `jiaodui/markers.py`：新增 `escape_marker_field` / `unescape_marker_field` / `is_v2_report`；扩展标记与屏蔽正则；`split_marked_body` / `audit_markers` 增加 `escaped` 参数。
- `jiaodui/report_suggestions.py`：新增 `extract_body`；删三处硬拒绝；写入侧转义；两个摘要分别校验；空正文拒绝。
- `jiaodui/verify.py`、`jiaodui/report_parse.py`、`jiaodui/docx_report.py`：按 §4 接线并把 v2 判据收敛到 `is_v2_report`。
- 测试：`tests/test_report_suggestions.py` 增补执行计划 §11.1 的场景（含竖线与括号的原文恢复无损、跨行/emoji/零宽/CRLF、空正文拒绝、短正文放行）与 §11.2 的反向用例；v1 冻结语料逐份标注预期不变。

## 替代方案与否决理由

- **换分隔符（如 `⟦⟧`）**：要同时改 v1 解析、Word 渲染与全部历史报告，风险远大于收益；D2 已否决。
- **相似度 / 模糊匹配补偿**：违反"严格相等"不变量，不做。
- **在 v1 上也启用转义**：会改变老报告里字面 `\|` 的语义，破坏冻结语料的既有预期，不做。
- **靠校验失败来发现不可无损承载**：现状就是这条路——它把编码问题伪装成流程失败，且失败发生在闸门之前，诊断信息指向错误方向。

# ADR-0001：M5 多学科入口与逐科落地

- 日期：2026-09-29
- 状态：入口与分层决策已采纳；逐科实现、验收待执行。
- 范围：高中物理 M1 之后，其余六个预设学科的入口、流程差异与上线条件。
- 关联：[PRD](../PRD.html) 的 D7、D17、D22–D27、§5、§7、§10；[实施清单](../IMPLEMENTATION.md)。
- 边界：本 ADR 细化 M5，不改变 PRD 的产物契约，不跳过 M2 质量评估，不代表其他学科已支持。

## 1. 背景

高中物理已完成 M1 端到端竖切，但这只证明一条实际材料处理链路可运行。当前只有高中物理具备学科 references 和配置，其余六科在学科矩阵中仍为「M5 待落地」。

原入口直接使用高中物理拆分参数，并假设用户已经提供学科。扩展后，用户应可以直接提交材料，由主 agent 决定采用哪套学科规范；用户已指定学科时，不应再次为识别学科读取文件或重复确认。

原有「主 agent 不读源文」约束用于维持单元上下文隔离。入口识别所需的少量节选与逐单元读取全文不同，因此允许前者，同时保留后者的隔离约束。

各科还可能有不同的前置步骤与检查顺序。例如，学科矩阵中的小学语文要求先审答案，高中语文涉及古诗文参考。M5 需要容纳这些差异，同时避免复制多套完整调度与交付流程。

## 2. 决策

### 2.1 由主 agent 在总入口完成学科路由

主 agent 读完入口 skill 后，先确定影响执行的学段、学科与材料类型，再进入相应处理流程。

| 入口情况 | 行为 |
| --- | --- |
| 用户已明确学科 | 直接采用，跳过学科识别预览；仅补充会影响执行的缺失信息 |
| 未指定，但描述或文件名已足够明确 | 直接判断，简短告知处理口径后继续 |
| 信息不足，需要查看材料 | 主 agent 按需节选标题、目录或有代表性的少量正文 |
| 节选后仍有歧义、证据冲突或疑似混合学科 | 向用户询问当前阻塞执行的问题，不强行选定单一学科 |
| 已识别，但该学科或材料模式尚未落地 | 明确说明当前支持范围，不套用高中物理流程 |

有限预览遵循[入口 skill §2.1](../../skills/jiaodui/SKILL.md)：默认每份材料一次、合计不超过 2,000 字符，够用即停；批量先设总预览量上限。在工具返回进入主上下文前限定范围，不先读取全文再截取。

预览如依赖格式转换，可先做所需环境检查和 `convert`，仅向主 agent 返回节选；学科未确定前不做学科相关清理或拆分。后续复用同一源文件的转换产物。

默认不派专门的识别子 agent。需要跨章节检查或复杂批量分类的预检能力，作为后续独立设计，不纳入常规入口。入口识别也不替代校对子 agent 的真实本地读图能力验证。

### 2.2 一个入口，按需加载学科规范，共用调度与交付

沿用 D22 / D23 的组织方式，不为六个学科各复制一个完整 skill，也不新增一层「学科总管 agent」。

| 载体 | 职责 |
| --- | --- |
| `skills/jiaodui/SKILL.md` | 入口判断、通用流程、调度与硬约束，保持小于 8,192 字符 |
| `references/subject-matrix.md` | 学科索引、已支持的模式与限制、落地状态及特殊步骤摘要 |
| `references/subjects/<学科>.md` | 学科检查重点、必要的前置步骤与检查顺序、特殊核验要求 |
| `config/subjects/<学科>.json` | 工具集、输入扩展名、拆分等确定性参数 |
| `jiaodui/` | 可复用的确定性处理能力；CLI / MCP 不承载业务判断 |

学科规范宜先给主 agent 可读取的流程摘要，再展开单元校对细则。主 agent 按需读取所选学科的流程说明；单元子 agent 接收对应规范与材料的路径，自行读取内容。其他学科的长文不必一起载入。

学科特有步骤由主 agent 在现有一层扁平结构中组织。公共的滑动窗口派发、失败处理、报告校验、状态恢复、报告拼接和 Word 交付继续只维护一份。

PRD 中「共性流程零改动」的目标是避免逐科复制或特判公共流程，不是禁止修复通用缺陷。若真实材料证明配置无法表达必要的确定性差异，应先复核 PV2，再在 `jiaodui/` 内补充能力与测试，不能把业务分支塞入 CLI 或提示词命令拼接中。

### 2.3 支持状态以逐科验收为依据

学科识别成功、配置文件存在、某个计算工具可调用，都不等于该学科已支持。只有完成相应材料模式的端到端验收，才更新矩阵中的支持状态。

以下为 M5 的迁移范围，不是已实现清单，也不是固定排期：

| 学科 | 迁移与验证重点 | 当前状态 |
| --- | --- | --- |
| 高中化学 | 配平与计量实算、化学用语、讲义例练边界；试卷规则需用真实材料确认 | 待落地 |
| 小学数学 | 数值与几何核验、图文一致性、讲义边界；现有目标配置仅覆盖 lecture | 待落地 |
| 高中语文 | 古诗文参考的使用与缺失说明、通假字等不误标、共享材料与题目边界 | 待落地 |
| 高中历史 | 史料与年份核对、章节 / 模块 / 模型大招 / 例练边界 | 待落地 |
| 初中英语 | 语法 / 拼写 / 词形、例题精讲边界、共享阅读材料与小题的完整性 | 待落地 |
| 小学语文 | 先审答案再校正文、答案准确性与解析逻辑、班型与例练边界；现有目标配置仅覆盖 lecture | 待落地 |

上表依据[学科矩阵](../../skills/jiaodui/references/subject-matrix.md)，具体边界须由真实样本验证。某科只完成讲义验收时，明确标为仅支持 lecture，不能据此宣称试卷也可用。

高中语文的 `classics` 自动前置检索仍属于 M6。M5 可以定义和验证已有参考的使用方式；缺少参考时明确注明「无前置参考可供比对」，不能宣称已完成权威原文核验。独立解题、批注评审和自由校对也不因扩学科而自动启用。

### 2.4 交付契约不按学科分叉

所有学科继续遵守 PRD §5：

- 单元子 agent 只接收路径与要求，不修改源文件、不嵌套派发、不自由命名运行产物。
- 新报告必须通过 `verify-report`；`parse-report`、`build-report`、`build-docx` 复核当前状态，不消费未通过报告。
- `status` 从磁盘产物推导完成状态，保留旧失败记录不使已修复单元回退。
- 校验失败自修不超过 3 轮；仍不过则按契约写 `_校对失败.md`，保留最后一次 verify 完整输出和产物摘要；技术性失败最多重派一次。
- Word 交付复核实际产物：错误标记数 = 批注锚点数 + 公式可见兜底数，缺失数为 0。

入口路由不新增自由命名的运行状态文件，也不把会话中的学科判断作为单元已完成的依据。

## 3. 落地路径

### 3.1 保留 M2 的前置门槛

按现有 PRD，正式扩学科仍以 M2 / M3 质量门槛通过为前提：冻结的 22 个单元跑两遍，两遍首次通过数均至少 20/22、差异不超过 3 个单元，并完成旧有新版无的解释与人工质量复核。

入口决策、ADR 与逐科准备工作可先整理；这些工作不能作为 M2 已通过或 M5 已完成的证据。若需要调整里程碑顺序，另行记录决策。

### 3.2 每次完成一个学科的可验收范围

1. **冻结范围与样本。** 明确本次支持的学段、模式和输入格式；记录真实样本路径、哈希、特征及预期检查点。旧仓仅作只读参考，不是运行时依赖。
2. **迁移学科规范与配置。** 先复核旧提示词和拆分参数，再整理为新仓 references 与配置。写清前置步骤、检查顺序、工具核验和已知限制，不原样搬入旧 agent 循环或凭证逻辑。
3. **补齐确定性能力。** 有缺口才改 `jiaodui/`，按行为契约先写失败测试再实现。已有化学、几何工具的存在仅说明可复用，仍须验证实际输入与结果。
4. **验证分发。** 新学科配置需要随包可用；当前包内配置在 `jiaodui/data/subjects/`，须与仓库配置一致，验证仓库外安装后的查找与执行。
5. **真实端到端运行与人工复核。** 完成入口、拆分、子 agent 读图 / 校对 / 落盘、verify、汇总与 Word 交付。记录失败、误标和漏检，修复后复验。
6. **更新支持状态。** 通过验收后再更新学科矩阵，并链接可复现的验证记录。部分模式通过时只声明该范围。

首个新增学科建议优先考虑高中化学：现有核心已有配平与计量操作，[基线记录](../BASELINE.md) 也包含化学真实产物，便于检查迁移结果。此项是实施建议；六科的具体顺序与样本范围尚未确定。

## 4. 验收

### 4.1 入口行为

在宿主真实运行记录中验证以下路径。不能只靠匹配 skill 文本或模拟返回，声称主 agent 已按要求查看材料、提问或跳过读取。

| 场景 | 应观察到的行为 |
| --- | --- |
| 用户明确提供已支持学科 | 无用于学科识别的材料读取或额外识别子任务，直接加载相应规范 |
| 未指定，描述 / 文件名已足够 | 不机械读取正文，不重复确认已知信息 |
| 未指定，需要正文证据 | 仅有限节选进入主上下文，确定后停止读取并路由 |
| 学科或学段仍不明确 | 询问用户，未擅自启动依赖学科的清理、拆分或校对 |
| 未落地学科 / 模式 | 明确说明不支持，未回退到物理配置 |
| 预览依赖转换 | 转换先检查所需环境，主上下文只收节选；后续复用转换产物 |

### 4.2 单学科完成条件

- 每个宣称支持的材料模式至少有一份完整真实材料跑通，并覆盖该范围内必要的图片、公式、共享材料或特殊题型；不能只用孤立短题替代整份材料验收。
- 拆分后题干、共用材料、答案、解析和图片关系经人工核对，不能仅以「没有空单元」判定拆分正确。
- 对纳入交付的单元逐一验证新报告契约；不合格报告必须被拒，人工确认合格的报告必须被接受。旧报告逐份标注兼容预期，不统一冒充新契约合格样本。
- 完成人工内容复核，误标、漏检及旧流程发现而新流程未发现的问题都有明确处理结论；没有未处理的严重内容错误。
- 实际 Word 产物满足锚点覆盖要求；失败清单可见，不能把部分单元失败的运行记录写成全部成功。
- 变更确定性代码时运行 `.venv/bin/pytest -q`；公共能力改动须覆盖高中物理回归。宿主能力、落盘和读取行为另做真实冒烟。
- 验收记录包含代码版本、样本哈希、宿主 / 模型、运行命令、校验结果、人工结论和限制；可取得的 token 用量如实记录，不可取得时注明，不能估算为零。

六科都完成各自声明范围的验收，M5 才算完成。单科通过可以逐科开放，不等待其余学科全部完成；未通过项继续标为待落地。逐科质量样本的具体数量与量化阈值须在运行前确定，本文不把 M2 的 22 单元数字机械复制为每科要求。

## 5. 备选方案与取舍

| 方案 | 结论与理由 |
| --- | --- |
| 每次派识别子 agent | 不作为默认。增加派发和回传；简单材料可由主 agent 有限预览判断。复杂结构预检可后续单独设计 |
| 所有材料都要求用户先选学科 | 不采用。用户可指定，也应允许提交材料后由主 agent 判断；只有疑问时才询问 |
| 主 agent 通读全文再路由 | 不采用。识别不需要常规全文阅读，容易扩大主上下文；明确节选边界即可 |
| 每科一个完整 skill 或学科总管 | 不采用。公共约定容易漂移，且额外管理层不符合当前扁平调度约束 |
| 所有差异塞进配置或 CLI 分支 | 不采用。学科判断与检查顺序由 agent 执行，确定性参数和算法留在 Python |
| 一次迁移六科后统一验收 | 不采用。逐科完成真实链路，能在扩散前暴露问题，也便于明确支持范围 |

## 6. 后果与待定项

正面影响：用户无需总是手工选择学科；已明确学科时没有额外识别步骤；学科差异可渐进加载；确定性核心、报告契约和交付路径继续共用。

代价：主上下文会保留少量入口节选；预览后的误判仍需通过疑问提问与真实样本评估控制；每科都需要可复现的材料与人工复核。本文不承诺具体成本节省比例，也不假定子 agent 或主 agent 在相同证据下天然更准确。

以下事项不在本次决策中假定已解决：

- 六科的具体排期、首批材料和每科最终支持的模式 / 格式范围。
- 各科学科规范中的完整前置步骤及质量评估样本数量、阈值。
- 批量总预览预算是否需要统一数值；当前由主 agent 在读取前设定，依据真实运行再收敛。
- 混合学科整卷、复杂批量分类和专门预检子 agent 的后续设计。
- 历史 / 语文的拆分差异能否完全配置化（PRD PV2）；若不能，先记录证据再调整设计。

本 ADR 不包含六科的实现代码。入口规范已更新，但新增入口行为的宿主冒烟、M2 质量验收和 M5 逐科验收仍需分别取得运行证据。

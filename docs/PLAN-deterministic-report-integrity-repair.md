# 计划：确定性重建校对报告原文完整性

## 目标

增加一个显式、确定性的报告修复步骤：以单元源文为唯一原文依据，将报告中的有效校对标记插回源文对应位置，修复模型转录未标记正文时引入的字面差异。

保持现有严格契约：普通正文及公式仍须逐字一致；不采用相似度阈值、模糊匹配或宽松 LaTeX 等价判断；无法唯一定位时拒绝自动修复。修复不判断“修改后”及修改原因是否正确，verify-report 仍是进入下游的唯一闸门。

## 问题背景

续测单元3的源文公式含有 {10}^{-2} 与 {10}^{-3}，报告未标记正文写成 10^{-2} 与 10^{-3}。数学意义相同，但字面不同。verify-report 因整段不匹配，同时报告源文段缺失和报告段多出；两个错误是同一个段落差异造成的联动结果。

三次报告自修后差异仍在。失败记录只说明修过公式原文，没有保存每轮具体改动，无法证明花括号已逐字恢复。改进方向不是放宽校验或增加模型重试，而是由程序以源文重建报告正文。

## 设计原则

1. **源文是唯一真值**：重建后的标记原文正文来自单元源文，不来自模型重新抄写的未标记文本。
2. **标记只表达意见**：标记原文字段必须在源文中唯一、逐字定位；修改后和原因原样保留，不由修复器改写或裁定。
3. **严格匹配，不模糊猜测**：不做相似度阈值，不删除公式花括号，不归一化数学表达式。换行规范化仅沿用现有文件读取契约，不改变正文字符。
4. **失败关闭**：字段找不到、重复命中、标记重叠、顺序冲突或报告结构异常时，不写文件，返回字段编号、原文片段和候选位置。
5. **修复与验收分离**：修复器不能代替 verify-report。候选报告先通过文本和图片检查，落盘后再由完整 verify-report 复验；通过后才可 parse-report。
6. **只写契约文件**：只允许更新单元内的 _校对报告.md；不改源文、失败记录或其他产物，不创建持久化 attempt / 副本。所有写入路径校验工作区真实路径。

## 当前实现依据

- jiaodui/markers.py 已定义统一内联标记解析器、split_marked_body 和 audit_markers。split_marked_body 仅把标记替换为标记内的原文字段，不能恢复标记外被转录改动的正文。
- jiaodui/verify.py 的 _check_integrity 与 _align_paragraphs 执行严格逐段对齐；verify_unit 还执行图片资源闸门。该校验必须保持只读。
- jiaodui/report_parse.py 将报告解析成 corrections、summary 和 marked_text；登记仍须在完整闸门之后。
- jiaodui/cli.py 注册命令参数。CLI 壳只负责解析和输出，修复逻辑放入 jiaodui 核心。

## 实施方案

### 1. 新增纯函数修复核心

建议新增 jiaodui/report_repair.py。输入源文和报告全文，输出可修复候选或结构化拒绝诊断；纯函数阶段不写文件。

处理顺序：

1. 用现有章节解析器定位头部、标记原文、修改原因；只重建标记原文章节，保留报告其余部分。
2. 用现有标记解析器解析全部标记。先拒绝语法无效、编号重复及已知报告结构错误。
3. 对每个标记的原文字段在源文中作严格定位。V1 只接受唯一匹配；零次或多次均拒绝，避免将重复短语错标到另一处。
4. 要求标记位置顺序单调且区间不重叠。以源文字符偏移量为准，在源文上插入原报告中对应的完整标记字符串，形成 canonical marked body。
5. 候选正文除标记插入外全部来自源文，因此未标记公式、标点和空格均原样恢复。修改后和原因不变。
6. 对完整候选报告运行现有文本校验，并检查图片资源。任一检查失败均不落盘。

V1 不自动处理重复原文字段。若字段在源文中有多处匹配，即使上下文看似接近也拒绝；后续若增加上下文锚点定位，必须另立测试证明确定性。

### 2. 增加显式 CLI

建议新增 jiaodui repair-report --unit <目录>：

- 默认预览：报告可修复性、标记定位摘要和候选差异，不落盘。
- 显式 --apply：仅当字段唯一定位、候选文本校验通过、图片检查通过时，原子替换规范文件 _校对报告.md；之后运行完整 verify-unit 复验。
- 写入模式要求传与会话一致的 --work-root，并使用现有工作区 realpath 安全检查。
- 应用后不自动调用 parse-report。主流程确认 verify-report 通过后，再单独登记。
- 新命令在 CLI 壳中只做参数解析和结构化结果输出；业务判断留在核心模块。
- 不让 verify-report 在发现错误时暗中修文件，避免只读闸门产生副作用。

若实现者认为新增命令过重，可选择等价的显式 CLI 子命令，但不得把修复隐式嵌入 verify-report。

### 3. 错误、原子写入与留痕

- 字段不匹配或不唯一：返回结构化拒绝结果，报告字段编号和候选位置；保持报告原字节不变。
- 应用前完整校验候选报告及图片；使用同目录临时文件和原子替换，只修改契约报告文件；临时文件无论成功或失败都清理，不成为交付产物。
- 应用后完整 verify-report 失败时，不 parse、不汇总、不生成 DOCX；按契约留存完整错误与摘要。源文不得修改。
- 不删除既有失败历史来掩盖此前失败；新轮次及 action 应遵循材料记录和状态契约。

## 测试计划

新增 tests/test_report_repair.py，并扩展 CLI / 流程测试。

### 正向测试

- 报告含有效、唯一的标记，但未标记公式把 {10}^{-2} 转成 10^{-2}；预览显示差异，应用后公式从源文恢复，verify-report 通过。
- 单个与多个不相邻标记均正确插回；编号、修改后、原因、严重度、报告头部和图片引用保持不变。
- 中文、LaTeX、转义竖线及契约支持的跨行标记在唯一匹配时正确插回。
- CRLF 按当前文本读取契约处理，正文字符保持严格一致。

### 拒绝测试

- 原文字段在源文中找不到或出现多次。
- 标记位置乱序、重叠、重复编号或语法错误。
- 修改原因、严重度或报告其他契约本身无效。
- 候选文本校验或图片检查失败。
- --apply 被拒绝时，断言报告原字节、源文和其他文件均不变。

### 严格闸门回归

- 直接 verify-report 仍拒绝所有未标记正文变化。
- 无唯一定位时不得用相似度或“最接近字符串”兜底。
- 修复候选仍必须通过完整 verify-report；parse-report 与 build-report / build-docx 继续拒绝未通过报告。
- 测试预期使用独立构造的源文和报告，不用修复器生成预期值。

## 实施顺序与验收

1. 为纯修复核心先写失败测试，锁定唯一匹配、重复匹配拒绝、非标记正文取自源文、其他章节不变和拒绝时无副作用。
2. 实现源文偏移定位、标记插入及候选报告构造。
3. 接入预览和显式应用 CLI，增加工作区路径安全、图片检查和完整复验。
4. 同步 skill、failure-modes、CLI 文档与双副本测试。
5. 执行定向测试、全量测试和 CI 口径测试：.venv/bin/python -m pytest -q；.venv/bin/python -m pytest -o addopts='' -q -rs。
6. 使用单元3当前源文/报告作为回归样本：预览应定位花括号差异；应用候选应恢复源文字面文本并通过严格 verify-report；确认源文哈希不变。除非另有授权，不自动登记、不生成整卷报告或 Word。

完成判据：

- 单元3这类未标记 LaTeX 转录差异由源文重建修复，仍按严格字面匹配通过。
- 无法唯一定位、标记结构错误或图片 / 文本校验失败时拒绝应用，原报告不变。
- 不修改源文，不改写修改后或原因，不绕过 verify-report，不自动 parse 登记。
- 现有双向校验、图片闸门、下游拒绝语义、路径边界和退出码契约保持。
- 两份 skill 副本一致，新增和既有测试通过。

### 现行契约摘录

- 标记原文应逐字抄录单元源文正文，仅在需修改处插入内联标记。
- 完整性闸门去掉标记语法、以各标记原文字段还原正文，再与单元源文逐段比对；可确定的缺段、重段或未标记正文变化均拒绝。
- 无法定位标记的 warning 不等于允许改变可确定的普通正文；不能把 locate.unknown 和 integrity.changed 混为一谈。
- verify-report 是模型产出与下游之间的唯一闸门。修复命令只能生成候选，不能自行宣告交付完成。
- 修改范围限报告，不自动修改源文件；失败须保留最后一次完整 verify 输出和产物摘要。

## R1 · P1：表达式绕过计算沙箱，获得子进程文件写入能力

位置：[templates.py:48](../jiaodui/calc/templates.py#L48)、[safety.py:3](../jiaodui/calc/safety.py#L3)、[sandbox.py:23](../jiaodui/calc/sandbox.py#L23)。

触发：通过 `run_operation('evaluate', expression=...)`，使用 `sqrt.__globals__` 访问其模块的原始 builtins，通过拆分字符串取得 import，再导入 pathlib，对授权工作区外的临时标记执行 touch。这个路径同样经过正常 operation 参数校验、模板生成、`check_dangerous` 与子进程。

实际结果：`success=true`、`result=null`；临时标记确实存在，`marker_inside_work_root=false`。具体输入见 [evidence.json](review-2026-10-13/evidence.json) 的 R1。所有文件都在自动清理的合成临时目录中，没有修改真实材料或测试环境。

根因：`parse_expr` 会求值 Python 表达式；提供数学函数白名单仍会暴露函数对象的 globals。黑名单匹配明文危险词，字符串拼接绕过检测；子进程的受限 builtins 不影响 SymPy 函数所在模块持有的原始 builtins。子进程只有超时与进程分离，没有操作系统权限隔离，也没有调用 `ensure_inside` 约束这些副作用。

影响：模型或材料驱动的非数学表达式可能在 CLI 进程权限范围内执行导入和文件操作，绕过核心产物路径约束。“受限 builtins + 黑名单”不能被描述为安全权限沙箱。复现只证明了文件创建与导入；未执行网络、凭证读取或破坏性操作。

建议：在求值前采用明确的数学语法白名单，拒绝 dunder、任意属性访问、动态索引、非许可调用等执行入口；几何链式调用需单独定义允许方法，不能简单禁用所有点号。避免把用户输入直接交给 Python eval 语义；必要时以无网络、限定可写目录的系统级沙箱提供第二层隔离。修复需兼顾合法数学函数、代入、矩阵、Piecewise、几何链式调用与量纲声明。

验收：上述输入及等价变体被拒绝且不创建文件；正常数学与几何用例仍可接受。不要只新增这一条字符串的黑名单，否则同类绕过仍存在。

## R2 · P1（已修复，c5af354）：旧 attempt 的迟到技术取消终结正在运行的新 attempt

位置：审查基线 [material.py:758](../jiaodui/material.py#L758)；修复后的拒绝逻辑见 [material.py:888](../jiaodui/material.py#L888)。

触发序列：同轮同单元 A 进入 read → parent 技术超时取消 A → 显式撤销停止 → B 进入 read → A 的超时回调再次提交技术取消。取消请求中的 expected_run_id 正确，但 attempt_id 属于已经终结的 A。

审查基线实际结果：B 从 `phase=read, in_flight=true` 变成 `phase=cancelled, in_flight=false`；`terminated_attempts` 同时包含 A 和 B 的 cancelled；`dispatch-plan.stop=true`。取消记录写着 attempt-A，被更新的当前 state 却仍是 attempt-B / agent-B。证据见 R2。

**修复后（当前代码，c5af354）**：同一序列的最后一次迟到取消在写盘前被 `attempt-terminated` 拒绝；`before` / `after` 均为 attempt-B `read`、`in_flight=true`，`terminated_attempts` 仅含 attempt-A，`dispatch-plan.stop=false`。回归测试 `tests/test_unit_progress.py::test_late_technical_cancel_cannot_stop_replacement_attempt` 覆盖该序列及“当前 B 仍可取消”的双向契约。当前复跑证据见 [evidence-2026-10-23.json](review-2026-10-13/evidence-2026-10-23.json)。

根因（审查基线）：`record_unit_cancel` 校验轮次和取消来源，没有校验技术取消目标是否是当前 attempt。代码直接改变当前 unit_state，并终结其中的 attempt_id，而不是取消请求指定的 attempt_id。

影响（修复前）：异步超时或重放收尾回调能够误停新的校对尝试，并停止整份材料补位。这是正常恢复过程中可触发的竞态，不依赖伪造用户取消。

建议：技术取消绑定当前 unit / run / attempt；已终结或已替换 attempt 的迟到取消拒绝或幂等返回，不写当前 state、不引入新的全局停止。用户取消仍按用户意图停止，不能为了技术 CAS 保护而削弱用户取消。撤销也应准确关联对应取消事件。

验收：锁住上述 A→B 序列，B 保持在途且不会新添 stop；当前 B 的技术取消仍可停止；同轮用户取消不可被技术事件覆盖。被拒旧取消不改变磁盘记录。现状：已由上述回归测试与当前复跑覆盖。

## R3 · P2：按小数位舍入，损坏小量计算的有效精度

位置：[templates.py:61](../jiaodui/calc/templates.py#L61)、[templates.py:79](../jiaodui/calc/templates.py#L79)。

触发：`run_operation('evaluate', expression='pi*1e-12')`。

独立期望：标准库 `math.pi * 1e-12 = 3.141592653589793e-12`。实际返回 `success=true, result=3e-12`，相对误差 `0.04507034144862789`，约 4.51%。证据见 R3。

根因：注释说“12 位有效数字”，实现却是 `round(val, 12)`，即小数点后 12 位。保护条件 `1e-10 * max(1, abs(val))` 在小量处退化为过宽的绝对容差，使相对误差明显的结果仍被当作去噪后的有效值。

影响：小时间、微小物理量或数值核验可能以 success=true 返回失真的结果，并进入计算证据。大部分常见整数和常量测试不会揭示问题。

建议：优先保留计算数值，展示去噪与证据值分离；或采用真正有效数字舍入并以适当相对误差约束。两个分支的公共序列化行为应统一，避免浮点与 SymPy Number 返回口径不同。

验收：跨数量级的独立已知值保持合理相对精度，包含 `pi*1e-12`、负小量与正常大数；原有 IEEE 噪声示例也应保持可读。期望值来自标准库或独立规格，不复制实现中的 round 逻辑。

## T01：导入图片解析与来源

问题：相对引用 `a.png` 与 `nested/a.png` 被 basename 查找误合并；外部 Markdown 原图消失后重转，会无声使用上轮 raw 图片。

预期行为与验收：

- 按正文完整路径解析优先于 basename 回退；同名不同图各自保留，并沿用内容哈希命名。
- 精确路径找不到时允许既有 basename 回退；不同内容的候选不能任取，保留引用并输出缺失/冲突诊断；相同内容候选可接受。
- 再次转换外部 Markdown 时只使用本次源目录资源；原图缺失必须报告，不能由旧 raw 输出补齐。
- 明确以材料 `source/` 副本作为转换输入时，可继续使用该副本自身的相对资源。
- 转换资源变化应使当前轮次失效，不能继续把上轮单元视为完成。

实现范围：图片归置与 Markdown 源目录选择；不新增资源库、事务框架或宿主读图审计。保留现有工作区边界、哈希重命名、旧输出图片清理规则。

实现结果：

- 图片归置先查完整引用路径；裸文件名优先取正文所在资源基目录的文件，其余目录中的同名文件走回退。
- basename 回退按内容摘要核对候选；不同内容报告冲突并保留引用，同内容继续接受。
- Markdown 转换不再把旧 raw 输出加入源目录。原图缺失时报告 missing，沿用既有规则清理旧 raw 图片；源副本保留导入时资源，明确选择该副本作为输入时仍可复用。
- 沿用现有转换资源摘要比较开启新轮次，无需增加工作流状态机制。

验证记录：新增 9 个参数化/集成用例，覆盖路径优先、回退的接受/拒绝、外部缺图、旧完成失效及 source 副本复用。修复前首先观察到 4 个失败，补充裸文件名场景另观察到 2 个失败；修复后相关测试 132 passed。独立只读代码复核通过；全量验证 `.venv/bin/python -m pytest -o addopts='' -q -rs`：1201 passed、4 subtests passed（退出码 0）。本批完成，后续 tickets 留待下一批。

## T03：全量智能切片覆盖与明确节选

问题：只取源文第 1、3 行仍可登记两个完整单元，遗漏的第 2 行没有进入任何下游校验，最终可能宣称全材料完成。

预期行为与验收：

- 智能 slice 默认 full；按与预览相同参数清理后的源文行区间核对，所有非空行恰好覆盖一次，包含标题；空白行不强制覆盖。
- 全量漏行、重复覆盖、非法区间和全量 text 提案均在单元写盘前拒绝，诊断仅给行区间，不输出源文全文。
- 用户明确节选时声明 excerpt 和原因，允许漏行但不允许所选非空行重复覆盖；历史 text 仅保留为显式节选，覆盖标为未核验。
- 范围摘要写入当前参数与轮次动作；slice / precheck / 整卷报告 / Word 返回覆盖摘要。节选交付正文标出范围和原因，完成仅针对所选单元。

- 既有规则拆分、人工标记和整篇策略按原契约运行，历史未声明范围的材料不凭空标为全量已核验。

实现结果：以行计数和连续区间摘要实现写前核对；人工与整篇策略共用原写盘机制。新增 CLI 参数 `--scope` / `--scope-reason`，边界清单可使用同名字段。范围声明沿用 params/action 持久化和既有开新轮逻辑，不引入反向语义比对或复杂状态系统。

## T02：拆分名称写前预检、原题号答案映射

问题：重复边界名会先覆盖源文和图片、再因清单重复被拒绝；末尾答案原先按拆出顺序回填，节选或缺号试卷会携带别题的答案。

预期行为与验收：

- 按兜底规则得到的最终单元名必须唯一；重复时在材料集合回调和任何单元写盘前拒绝，返回 `duplicate-unit-name` 及重复名称列表。
- 既有材料的源文、图片、清单和交付产物字节不变；`--replace-units` 不能豁免重复名称检查。
- 输出目录继续连续编号；末尾答案按题干起始规则识别到的原题号回填。优先取唯一数字捕获；无数字捕获时只接受匹配前缀中的唯一数字，多个候选不猜测。
- 原题号无法识别、题干或答案编号重复时不猜测回填；有参考答案区但缺少对应条目时诊断中带输出单元名与原题号。
- 正常连续编号和随题答案保持原有行为。

实现结果：只修改拆分核心，增加最终名称计数预检；原题号从边界规则的数字捕获或匹配前缀识别，答案映射使用该编号。重复答案号从映射中排除，重复题干号跳过回填，诊断沿用 `SplitResult.warnings`。未引入备份、事务或新的状态机制。

验证记录：新增 16 个参数化/集成用例。首批 13 例修复前 12 failed、1 passed（随题答案对照）；独立复核发现首数字解析会误用前缀编号，补充含数字前缀、零宽捕获、多数字歧义 3 例，确认失败后修正。最终相关测试 149 passed；全量 `.venv/bin/python -m pytest -o addopts='' -q -rs`：1217 passed、4 subtests passed（退出码 0）；独立只读复核通过。本批完成。

## T04：圆几何约束、多解歧义、求导后代入

问题：`circle_from_two_points` 只联立两个方向约束就返回圆心/半径，得到的圆可能不经过撞击点（伪圆）；`formula` 多解时静默取第一个根；`differentiate` 声明了 substitutions 却完全忽略。

预期行为与验收：

- 圆轨迹按入射点切线方向与撞击面法向量联立真实约束；返回前必须校验两点到圆心等距与法向量指向入射点侧；条件冲突、约束退化明确报错（success=false），不得返回伪圆。
- `formula` 唯一解仍返回标量；多解返回 `{'ambiguous': True, 'solutions': [...]}`，且 substitutions 作用于全部根；无解返回 null。
- `differentiate` 先求导、再代入 substitutions；未给 substitutions 时行为不变。

实现范围：只改 `jiaodui/calc/templates.py` 三个模板与 `operations.py` 参数说明；不新增求解框架、不改沙箱五键返回契约。

实现结果：圆心由两方向约束的线性方程组解出（det==0 报约束退化），再校验等距与法向量方向；`formula` 解出全部根并统一代入，多解显式标 `ambiguous`；`differentiate` 求导后执行 `$subs_call`。同步 `operations` 帮助、skill 示例（含多解裁定与圆冲突说明）与 `calc-schemas.json`。复核后补：代入后按 simplify 差去重（E=0 时 ±根塌缩为唯一解，不再假歧义）；等距判定在纯数值语境按平方距离量级做相对容差（大尺度自洽浮点圆不再误报）；`entry_point` / `impact_point` / `velocity_direction` / `impact_normal` 强制恰为 2 元。

验证记录：首批新增 11 个用例（R5×4、R6×3、R7×4，另含既有对照）。修复前观察 8 failed（R5 伪圆/方向/退化 3、R6 多解 2、R7 代入 3）；修复后相关 16 passed。补充符号坐标验证：自洽符号输入正常出圆，冲突符号输入报条件冲突；法向量方向在符号不可判定时放行。独立只读复核确认 R5/R6/R7 主路径满足且无静默伪圆/首根/忽略代入，指出代入后未去重（P1）、等距绝对容差（P3）、方向向量长度未校验（P4）及测试缺口；据此补 5 个用例（塌缩去重、无解为 null、大尺度浮点圆、2 元校验、符号自洽圆）并收紧符号根断言。最终相关 61 passed；全量 `.venv/bin/python -m pytest -o addopts='' -q -rs`：1252 passed、4 subtests passed（退出码 0）。符号坐标配近似小数方向/法向量仍按 v1 边界明确报冲突（文档已注明先代入数值）；`formula` 不按 real 域过滤，复根也作为歧义解一次性返回。本批完成。

## T07：同轮用户取消不被技术事件覆盖

## T09：新材料人工 v1 兼容交付边界

状态：**2026-10-19 代码收口与自动回归通过，T09 关闭**。决策依据：[升级计划](PLAN-revise-tool-upgrade.md) D1 / P0-5、[PRD §5.5](PRD.html#s5-5)、[ADR 0008](adr/0008-anchor-evidence-interactive-errors.md) D1。默认拒绝、人工兼容不登记、v2/损坏/未知登记保护、下游拒绝与历史布局兼容已有正反回归；全量双口径通过（1437 passed，4 subtests passed），见 [P0 验证记录](REVISE-P0-VERIFICATION.md)。P0 整体的 ADR 采纳、人工样本核对与真实插件冒烟仍待验收，不因关闭本 ticket 而视为通过。

问题：有材料清单的新布局应以结构化提交与父复核为正常交付路径；若人工编写的 v1 报告经 parse 登记为本轮完成，就会绕过该边界。

已确定的预期行为：

- 新布局的 `parse-report` 默认拒绝 v1 报告，返回 `parse-v1-new-layout-forbidden`（exit 6）；显式 `--manual-legacy` 仍须 verify 通过，只写带 `legacy_manual: true` 的 `_校对数据.json`，不登记当前轮交付，不计入本轮完成。
- 已有 schema v2 数据、当前轮 v2 登记或数据损坏时，显式人工兼容路径返回 `legacy-overwrite-v2-forbidden`（exit 6），不覆盖既有数据；不能用人工 v1 结果降级 v2 交付。
- `repair-report --apply` 遵循同一人工兼容判定与 v2 数据保护规则。
- `status` 对带 `legacy_manual` 的结果判 `CURRENT_PENDING`，原因明确为“人工兼容交付，不计入本轮完成”；`build-report` / `build-docx` 拒绝消费。
- 无材料清单的历史布局，显式 `--legacy-layout` 的行为不变；兼容读取不冒充本轮结构化完成。

验收覆盖（代码与自动测试已通过；第 4 项中的人工/真实宿主证据待补）：

1. 默认新布局 v1 parse 被拒；显式人工兼容能写数据但不登记、不完成，下游均拒绝。
2. v2 数据、当前轮 v2 登记及损坏数据三种保护条件分别被拒，报告、数据与登记不被覆盖；修复 apply 与 parse 使用同一保护口径。
3. 无清单历史布局保持兼容，合格结构化 v2 正常路径仍可通过闸门与父复核；拒绝与接受两侧都要有独立预期。
4. 实现后记录相关定向回归及全量/CI 双口径结果；P0 整体出口的人工标注、ADR 评审与真实插件提交冒烟由主执行记录补证，不能由本文档替代。

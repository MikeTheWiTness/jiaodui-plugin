# 高中化学校对规范（人读）

输入为单元源文 Markdown（`第N题.md` / `单元N.md`）+ `images/` 配图。先判定内容类型，再按对应专项执行；判断由你（agent）做，配平、计量与数值由 `jiaodui calc` 做。产物与闸门见 `references/report-contract.md`，失败自修见 `references/failure-modes.md`，学科配置口径见 `references/subject-matrix.md`。

## 一、第 0 步：判定内容类型
- **题目**：含化学方程式 / 计算要求（“求某物质的质量”“计算产率”“求平衡常数”“求 pH”等），或选择题选项为化学量（如 `A. 0.1 mol`），或“题目 + 答案 + 解析”“本题考查……”“解析：”结构。
- **知识**：概念定义 + 方程式 + 性质描述为主，无“答案”字样的解析段；含实验步骤、反应现象归纳、配平规则讲解、物质性质对比表，目的是讲解而非考查。
- **混合**：讲解后附练习题（“练习：”“思考：”），或既有知识讲解段又有独立题目 + 答案结构。
- 执行顺序：通用检查 → 知识专项 → 题目专项 → 匹配度评估（混合时）。混合内容报告仍只输出一个 `### 标记原文` + 一个 `### 修改原因`（可由程序按结构化提案生成）。

## 二、通用五项（所有内容类型，强制执行）
1. **错词错字**：错别字、漏字、多字、词不达意。化学专有名词是重灾区：苯 / 笨、酯 / 脂、羰 / 碳、铵 / 氨 / 胺、蒸馏 / 蒸溜、催化剂 / 摧化剂。
2. **标点 / 格式**：标点误用、换行错误、题号与选项编号不一致；不用 `=` 代替有机反应箭头。
3. **化学用语规范**（化学独有，重点）：
   - **元素符号大小写**：`Na` 非 `NA`、`Co`（钴）非 `CO`（一氧化碳）、`Cl` 非 `CL`、`Mg` 非 `MG`。
   - **化学式下标与括号**：`H₂O` 非 `H2O`、`Fe₂O₃` 非 `Fe2O3`、`Ca(OH)₂` 括号与下标位置。
   - **方程式配平**：系数最简整数比；必须实算验证（见第四节），不得凭经验断言。
   - **反应条件**：`△` / 催化剂 / 通电 / 高温 / 点燃 / 加热标注完整且与反应匹配。
   - **状态与符号**：气体 `↑`、沉淀 `↓`、可逆反应 `⇌`、有机反应 `→`、离子方程式状态符号 `(aq)` `(s)` `(g)` `(l)`。
   - **离子方程式**：电荷守恒、物料（元素）守恒、强电解质拆分规则、弱电解质与沉淀不拆。
   - **化合价与离子电荷**：`Fe²⁺` 非 `Fe⁺²`，`SO₄²⁻` 上标位置正确。
   - **热化学方程式**：`ΔH` 符号与数值、单位 `kJ·mol⁻¹`、每种物质的状态标注齐全。
   - **物理量符号与单位**：`c`（物质的量浓度）/ `n`（物质的量）/ `M`（摩尔质量）/ `Vm`（摩尔体积）/ `ΔH`；单位符号 `mol`、`L·mol⁻¹`、`kJ·mol⁻¹`、`g·cm⁻³`、`Pa`。
4. **图片内容**（含配图时必做）：实验装置图 / 物质结构式 / 工艺流程图 / 数据图表是否与题干描述一致；装置连接与仪器标注、结构式成键与官能团、流程图物料走向是否正确。
   - **透明底线稿先合成白底再判读**：本流程 PNG 多为透明底黑线稿，直接读图会呈现空白。先按白底合成（转 RGB 时以白色填充）再判断；把“透明图看起来空白”当成读图失败会误判。
   - **读不到图即环境不合格**：完成白底合成后仍读不到图，回报失败，不得跳过。
5. **合规性**：敏感词、敏感人物、不良价值导向（暴力 / 歧视 / 封建迷信 / 历史虚无主义等）→ 标记并说明理由。

## 三、化学专项

### 3.1 题目专项
1. **题干严谨性**：已知条件是否充分（试剂用量 / 浓度 / 温度 / 压强 / pH / 催化剂）、数据是否自洽（元素守恒、电荷守恒、质量守恒）、反应在给定条件下是否真能发生、实验描述是否规范。
2. **解析自洽**：题目 → 答案 → 详解三者一致；推导每一步能由前一步与已知条件推出，不出现“跳过关键步骤直接给出错误结论”。
3. **配平与计量必须实算**：
   - 配平 → `calc chemistry_balance`（`equation="反应物 -> 产物"`）。
   - 质量 / 物质的量换算、限量试剂、产率、纯度 → `calc stoichiometry` 或 `calc evaluate`。
   - 平衡常数 / pH / $K_{sp}$ / 速率方程 → `calc solve` / `calc evaluate`。
   - 离子方程式电荷守恒、表达式等价 → `calc equality`。
   - **不得心算 / 估算 / 凭印象**（见第四节）。提交前按「结论断言 → calc `call_id` → 结果 → 假设与单位」建立覆盖清单，确保每个关键系数、物质的量与结论都有对应实算证据。
4. **答案校验**：数值结论、配平系数、物质的量比、产率与纯度都必须经工具实算确认；文字型答案核对化学用语规范。
5. **独立解题**：v1 **冻结不启用**（旧流程的 `independent_solve` 不在新契约内），答案对错的防线是「实算 + 人工抽检」，不要假装调用。

### 3.2 知识专项
1. **概念 / 定义准确性**：表述严谨、术语规范（物质的量 vs 摩尔质量、同素异形体 vs 同位素、水解 vs 电离、氧化 vs 还原）。
2. **方程式正确性**：配平、反应条件、产物是否符合反应规律；必要时用 `calc chemistry_balance` 验证。
3. **反应条件与实验描述**：温度 / 压强 / 催化剂是否合理；实验步骤是否通顺；器材与试剂选择是否正确；现象描述（颜色变化、沉淀、气体逸出、放热吸热）是否准确。
4. **计算示例验证**：讲义中的计算示例用 `calc stoichiometry` / `calc evaluate` 代入验证；无标准答案时只验算过程是否自洽。
5. **物质性质描述**：物理性质（颜色 / 状态 / 气味 / 溶解性 / 熔沸点）与化学性质（酸碱性 / 氧化还原性 / 热稳定性 / 特性反应）描述是否准确。
6. **结构与命名**：有机物的官能团、同分异构体数目、系统命名法（含立体异构标注）是否规范。

### 3.3 混合专项（知识-题目匹配度）
反应覆盖（练习题涉及的反应是否在前文出现并讲清）、难度对等（不要讲完定义就上竞赛题）、物质与条件一致（练习题的物质与条件能用前文知识求解）、推导可行（无需引入讲解未覆盖的新概念）。

## 四、calc 验算习惯（强制）

- 配平：`jiaodui calc chemistry_balance --subject 高中化学 --param "equation=Fe + O2 -> Fe2O3"`
  - 返回 `coefficients` / `reactant_coeffs` / `product_coeffs` / `balanced_equation` / `species`。返回的 `balanced_equation` 是**最简整数系数**版本；与原文系数不同时先判断是否等价（可同为最简比），再决定是否标错。
  - 方程式写法用 `->` 分隔反应物与产物，多个物种用 `+` 连接；状态符号、条件符号（`△`、`催化剂`）不写进 `equation`，它们由你按题面判断。
- 计量：`jiaodui calc stoichiometry --subject 高中化学 --param "balanced_equation=2H2 + O2 -> 2H2O" --param known_substance=H2 --param known_mass=4.0 --param target_substance=H2O`
  - `balanced_equation` 必须是**已配平**的方程式（先跑 `chemistry_balance`）；本工具只做质量→质量换算，返回 `known_mol` / `target_mol` / `target_mass_g` / `mole_ratio`。
  - 产率、纯度、限量试剂：先由 `stoichiometry` 得到理论量，再用 `evaluate` 按题面公式折算，把两次调用分别记为两条证据。
- 数值求值：`jiaodui calc evaluate --subject 高中化学 --param expression="0.1*0.5"`；带变量时用 `--param 'substitutions={"c": 0.1, "V": 0.5}'`。
- 方程 / 方程组（平衡常数、pH、$K_{sp}$）：`jiaodui calc solve --subject 高中化学 --param 'equations=["x**2/(0.1 - x) = 1.8e-5"]' --param 'variables=["x"]'`（把化学量按题面换成符号或数值再求解）。
- 等价验证：`jiaodui calc equality --subject 高中化学 --param 'expression_a="sin(x)**2 + cos(x)**2"' --param 'expression_b="1"'`（字符串参数要写成带引号的 JSON，如 `"1"`；否则 `1` 会被解析成整数而报类型错误）。离子方程式两边元素与电荷的守恒式可用它做等价核验。
- **不做量纲交叉校验**：本学科 `quantities` 为空表，`calc dimensional` 传入 `{"quantity": …}` 时没有量表可比对。化学一律按题面写**显式单位表达式**（`"mole/liter"`、`"gram/mole"`、`"kilojoule/mole"`、`"gram/milliliter"`）或 `"dim:…"`；不要臆造化学量名，也不要因为“量纲一致”就当作结论已验算。
- **系数与代数推导仍要看实算证据**：量纲或单位一致只能证明单位相容，不能替代系数或代数推导验证；对派生公式记录从题设方程、关键代入到目标式的实际 calc 证据。
- **多解必须自己裁定**：`solve` / `formula` 返回多个根时返回 `{"ambiguous": true, "solutions": [...]}`，不得默认取第一个；按化学语义（浓度不能为负、物质的量不能为负、pH 范围、$K_{sp}$ 只取正根）补假设或分域求解。
- **符号白名单与浮点容差**：`I` 不当作虚数单位、`S` 不当作 sympy 注册器、`alpha` / `beta` 不当作常数；比较结果用容差而非严格相等。结果只取数值结论，**不要粘贴工具原始输出**到报告。
- 工具不成功或结果明显不合理时，按已确认 execution_policy 及 unit-recovery 预算恢复；每类总次数不能因换 agent 归零。工具执行失败与“内容结论不一致”是两回事；表达式含义有争议、权限拒绝或用户取消时停止，不采信或猜测结果。

## 五、常见错误类型（重点扫描）
- **元素符号与化学式**：大小写错（`CO` / `Co`、`NA` / `Na`）、下标丢失（`H2O`）、括号缺失或错位（`CaOH2`）。
- **方程式**：未配平、系数非最简、漏写反应条件、可逆与不可逆混用（`=` 与 `⇌`）、气体沉淀符号漏写或误写、有机反应用错箭头。
- **离子方程式**：电荷不守恒、强电解质未拆或弱电解质错拆、反应物配比与产物不符、状态符号缺失。
- **物质的量与浓度**：`n`、`c`、`M`、`Vm` 混用；单位漏写或换算错（`mL` ↔ `L`、`g` ↔ `mol`）；标准状况条件被忽略。
- **热化学**：`ΔH` 正负号与吸放热不符、单位缺失、物质状态未标、方程式系数与 `ΔH` 不同倍。
- **化学平衡与电离**：平衡常数表达式写错、转化率与浓度换算错、pH 与 `c(H⁺)` 混用强弱电解质。
- **电化学**：正负极与阴阳极混淆、电极反应式配平与电荷守恒、电子流向与离子迁移方向写反。
- **实验**：仪器名称错、装置连接顺序错、除杂与检验试剂选择错、现象描述与结论不符。
- **有机**：官能团名称错、同分异构体漏数或多数、命名法不规范、结构简式漏写氢或键。

## 六、易错题型（重点验算）
- **多步反应 / 工业流程**：物料守恒逐段核对，中间产物与循环物质不能漏算；每一步的质量或物质的量都用工具实算。
- **限量试剂与产率**：先判断哪种物质完全反应，再算理论产量与产率；不可直接用投料量。
- **化学平衡与电离平衡**：平衡常数、转化率、pH、缓冲体系；多解时按化学语义裁定。
- **电化学计算**：电子转移数与物质的量对应、串联电路电量守恒。
- **热化学与盖斯定律**：方程式加减与 `ΔH` 同倍同加，状态必须一致。
- **滴定与误差分析**：标准液与待测液对应关系、指示剂选择、误差方向判断。
- 上述题型一律先实算、再下结论；拿不准就如实标注，不臆断。

## 七、首轮证据与修改建议自查（第7项）
- 假设：反应条件（温度 / 压强 / 催化剂 / 浓度）、标准状况与否、溶液体积是否可加和、近似条件（如忽略水解、忽略电离）；未涉及时说明不适用。
- 符号：`n` 不等于 `c`、质量分数不等于体积分数、产率不等于转化率、元素守恒不等于电荷守恒。
- 图文：真实打开每个实际图，保存引用序号、路径、正文位置和化学语义归属（装置 / 结构 / 流程 / 数据）；无图显式 not_applicable。
- 计算：带当前 task/unit 身份调用，保存工具返回 `call_id`、表达式及结果；不能编造“已验算”。
- 建议自查：real_issue（不是错误选项 / 转换差异 / 润色），replacement_semantics（不引入冲突），related_coverage（选项 / 解析 / 结论关联表述均核对），scope_and_uncertainty（不越界且无未解争议），severity（影响等级适当）。无问题需 no_issue_review 及简短核验依据；勾选自查不代表语义已被程序证明。
- **证据不足时先补核验**，不把解析扩写或符合题设的结论当成原文错误：工具没跑就先跑，配平没实算就先实算，条件没核对就先核对。

## 八、报告与边界
- 报告结构、标记语法、严重度、编号对应、原文完整性：见 `references/report-contract.md`。
- 自修 ≤3 轮；仍不过写 `_校对失败.md`，不阻塞批次。
- 新单元只通过 unit-submit 提交结构化建议，程序从不可变源文生成报告；**不改源文**。旧 Markdown 报告继续兼容 verify / repair，不能覆盖 v2 数据。
